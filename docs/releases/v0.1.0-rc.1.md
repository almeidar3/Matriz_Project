# Matriz 0.1.0-rc.1

**Estado:** candidata académica, não publicada.

## Incluído

- Aplicação Flask com interface, API e persistência SQLite.
- Container Docker executado através de Compose; o volume nomeado preserva a base de dados entre recriações do container.
- Blueprint Render para criar uma demo pública usando o mesmo Dockerfile e Gunicorn.
- Healthcheck HTTP em `/api/health`.
- Workflow GitHub Actions para executar testes unitários/de integração, E2E, verificação JavaScript e build Docker.
- Instruções de setup, execução e teste no README.

## Configuração local

Para execução local, requer Docker Desktop com Docker Compose. Copia `.env.example` para `.env`, substitui a chave de exemplo por uma chave aleatória local e segue os comandos Docker Compose no README. Depois de iniciar o serviço, executa `docker compose exec web flask --app app seed-demo` para criar os dados fictícios.

Para a demo Render, envia o Blueprint e o Dockerfile para GitHub e cria um Blueprint pelo Render Dashboard. O Render gera a chave, ativa cookies seguros e semeia os dados fictícios automaticamente. O serviço é público e não tem disco persistente configurado.

## Limitações

- Esta versão é apenas para a atividade académica; a demo não tem hardening ou garantias de produção.
- SQLite e contas demonstrativas são locais; não há serviço externo de base de dados nem gestão de contas de produção.
- A demo pública usa contas conhecidas e dados fictícios que podem ser modificados por qualquer visitante; não inserir dados reais.
- O serviço gratuito Render não tem disco persistente configurado; dados podem desaparecer ao reiniciar/recriar a instância.
- A publicação da release e da imagem não faz parte desta entrega.
- Build, healthcheck, fluxo de API e persistência Docker local foram verificados; o deploy no Render e a pipeline no GitHub ainda requerem a criação do Blueprint e checks verdes. Os resultados estão em `docs/verification.md`.
